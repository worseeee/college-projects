# 课程设计说明摘要

以下根据本地课程报告整理，仅作功能与实验方法说明，不替代复现实测。

（5）对于MQTT协议，完成设备连接、属性上报、设备属性设置、事件上报、订阅获取设备期望值这5个功能的界面设计和代码实现。

与设备端上报不同，查询设备数据属于“应用侧（北向 API）”操作，代码通过 Python 的 requests.get() 方法实现：

·数据解析 (Response)： 云平台收到合法请求后，会返回包含 HTTP 状态码 200 的 JSON 响应。代码通过 response.json() 解析该响应，提取出 data 字段中的最新属性缓存值，并将其更新至上位机的日志或展示区，从而实现了端到端的数据闭环。

(3) 设备属性设置 (Property Set)： 为实现反向控制，设备端需在连接成功后，主动 SUBSCRIBE（订阅）平台下发的属性设置 Topic ($sys/{product_id}/{device_name}/thing/property/set)。当外部应用请求改变继电器状态时，云端会向该 Topic 推送消息，触发上位机本地回调函数并最终通过串口驱动单片机动作。

长短连接的应用场景对比： 亲手编码实现了 HTTP 的一问一答和 MQTT 的发布/订阅后，我对两者的差异有了直观感受。MQTT 凭借其极低的网络开销和能够“被动监听云端下发”的长连接特性，证明了其在物联网双向实时控制场景中的绝对优势。
